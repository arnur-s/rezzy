## Additional confirmed defects and fixes

Severity: **P1** security, data integrity or duplicate customer delivery;
**P2** functional/reliability/accessibility failure.

| Severity | Defect / invariant violated | Root cause, resolution and regression evidence |
| --- | --- | --- |
| P1 | Telegram webhook secret derivable from a visible channel ID | `telegram-connect-channel` now generates independent cryptographic random secrets. Existing channels require reconnect; newly generated secret format/independence is tested. |
| P1 | Service-role media signing could expose another workspace's attachment | All three sending functions validate workspace/conversation path ownership before signing. Foreign paths and malformed paths are denied in helper and actual handler tests. |
| P1 | Concurrent sends/retries could deliver a customer message twice | A service-only transactional dispatch claim fences each message before provider I/O. Only definite rejection releases it. Network ambiguity or persistence failure after acceptance retains the claim. Real handler races and two-session SQL tests enforce one provider call. |
| P1 | A lost invoke response could mark an accepted message failed | `features/inbox/api/messages.ts` reloads authoritative server state and never overwrites it with client failure. Accepted messages and failed summary writes do not trigger duplicate delivery. |
| P1 | Contact saves could partially commit; concurrent phone replacement could merge two submissions | `save_contact` persists fields and the optional full phone set in one transaction with invoker rights/RLS. `set_contact_phones` locks the parent contact before replacement. Injected second-stage failures prove rollback; the concurrent test fails against the old function and passes with the fix. |
| P1 | New auth state could be overwritten by stale bootstrap/sign-out completion; private query data could survive identity changes | `AuthProvider` orders session revisions, ignores obsolete completions, handles bootstrap rejection and clears cached server state when the principal changes. Deferred-promise regressions exercise each ordering. |
| P2 | Merged contacts with multiple provider identities could select the wrong recipient or fail lookup | Telegram/WhatsApp recipient and WhatsApp dial-cache operations now include the actual channel identity. Handler tests use multiple identities. |
| P2 | Webhooks acknowledged storage failures, losing retry opportunities | Read/status/reaction/delete/echo persistence failures now propagate as retryable server errors; signed real-handler tests cover failures and successful replay. |
| P1 | Provider callbacks could modify a message on another channel with the same external ID | Webhook target lookup now includes the conversation's channel and receipt direction. Signed callback tests use colliding external IDs to protect this boundary. |
| P1 | A message committed before an attachment-write failure could permanently lose attachments on retry | Inbound duplicate handling repairs missing attachment positions and required backfills; attachment-row/backfill database errors remain retryable and ambiguous outcomes preserve adopted media. | P2 | Delivery/read callback arriving before outbound provider ID persistence was discarded | Meta send completion reconciles scoped raw ledger receipts; already-accepted retries repeat reconciliation without re-sending. ## Test architecture and verification

Provider tests execute the actual Edge Function handlers with signed realistic
payloads, the installed Supabase client and intercepted provider I/O. pgTAP
checks the actual local SQL authorization boundary. Race tests use separate SQL
sessions and lock gates, and fail on SQL/process errors. Browser tests create
random ephemeral local accounts, reject hosted targets, block external HTTP
requests and clean up data. No live provider credentials or customer data are
required.

CI now runs frontend validation, local database contracts/concurrency and a
separate Chromium/WebKit browser job. The browser suite covers authentication,
onboarding, contact create/edit/merge, member permissions, assignment, mobile
navigation, message scroll behavior, shared contacts and the safe sticker player.
The complete locale/theme/375px–1280px matrix applies to auth. Authenticated
workflows use English/light mode, with inbox navigation also at 375px; the
shared-contact fixture covers Cyrillic at 375px. Contrast assertions resolve
computed theme variables through a DOM probe, not every rendered control and
background composition. Computed text sizes, clipping and focus are checked in
the actual browser layout.

The generated font-floor check and the bounded Impeccable static detector pass;
the detector reports no findings on changed UI source.

## Release and remaining risks

1. **Owner: rotate/revoke the exposed development login and active sessions.**
   Review historical exposure; deleting current documentation is insufficient.
2. **Owner: enable hosted leaked-password protection** and verify Auth behavior.
3. **Release: apply all five new SQL migrations before frontend/Edge Functions.**
   Browser contact saves require `save_contact`; senders require dispatch and
   reconciliation RPCs. This audit neither pushes hosted migrations nor deploys.
   Receipt-index creation takes a write-conflicting table lock and removes only
   identical message/provider-event/status duplicates, retaining the earliest
   receipt and all raw provider events. The upgrade path was tested with legacy
   duplicates; schedule the hosted migration according to table size/traffic.
4. **Owner: reconnect existing Telegram channels** to replace derived webhook
   secrets. New connections already use random secrets.
5. **Operations: inspect ambiguous deliveries before releasing a dispatch claim.**
   No automatic timeout can safely infer whether a provider accepted a message.
   Receipt reconciliation failures preserve raw ledger data; an accepted-send
   retry or service-only replay can recover after a database outage. There is no
   new background replay worker or provider-side exactly-once guarantee.
   Provider media download/upload failures retain visible failed attachments;
   there is no automatic media redownload worker. Historical inbound events
   already marked processed are not proactively scanned for missing attachments.
6. **Performance/UX follow-up:** benchmark the large initial bundle on target
   devices before choosing further splitting. Dark overlay hierarchy, every
   compact touch target, every route at 320px/200% zoom, and screen-reader use
   require broader contextual review. Representative checks are not a claim of
   universal WCAG conformance.
7. **External verification:** real provider token expiry, production webhook
   registration, hosted migration rollout and successful Vercel redeployment
   require owner-controlled environments. Local mocks/contracts cannot prove
   those live integrations. Production remains unchanged by this audit.
